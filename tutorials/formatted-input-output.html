01The mental model: formatting is a contract

Functions such as printf and scanf use a format string as a compact description of how data should be converted. The format string and the arguments must agree about types. When they do not agree, the result is not merely “a strange output”; in many cases the program has undefined behavior.

Output

printf takes values and converts them into text.

Value → format rule → characters

int age = 25;
printf("Age: %d\n", age);

Input

scanf reads text, converts it, and stores the result through pointers.

Characters → format rule → object in memory

int age;
scanf("%d", &age);
Core distinction in printf, width and precision describe how output is displayed. In scanf, width describes the maximum number of input characters consumed. Similar syntax, different job.
How this handbook is ordered

Sections 01–03 build the shared grammar. Sections 04–07 then introduce the output controls one at a time — width alone, precision alone, each flag alone — and only after that does Section 07 combine them and explain which control wins when two disagree.

Sections 08–11 apply the finished grammar to one data type at a time: integers, floating point, strings, and finally the length modifiers that change the assumed argument type. Sections 12–15 turn to input, from single characters to whole lines. Sections 16–17 replace the console with character arrays, which is where sscanf, sprintf, and snprintf enter and where the null terminator earns its own section.

Nothing in an earlier section depends on a later one. Every example uses only the notation already introduced.

02Anatomy of a printf conversion

The general shape is:

%flagswidth.precisionlengthspecifier

Only % and the final conversion specifier are normally required. Everything in between is optional.

printf("%+08d", 452);
        │││└─ d  : decimal integer
        ││└── 8  : minimum field width
        │└─── 0  : pad with zeroes
        └──── +  : always show the sign
+0000452

That single conversion already uses three optional parts at once. Sections 04 to 06 take them apart and introduce one per section; Section 07 puts them back together.

The scanf grammar is different

%*widthlengthspecifier

For scanf, * means “match this input but do not assign it.” There is no output-style +, -, #, or 0 flag system.

04The first control: field width

A number between % and the specifier is a field width: the minimum number of characters the conversion may occupy.

4.1 Width is a minimum, not a maximum

printf(":%4d:\n", 10);
printf(":%4d:\n", 45646546);
: 10: :45646546:

The field expands when the converted result needs more characters. Width by itself never truncates a number or a string.

4.2 The default is right alignment with spaces

When the result is shorter than the field, the padding goes on the left, so the value ends flush with the right edge of the field.

printf(":%8d:\n", 452);
printf(":%8.2f:\n", 4.49);
printf(":%8s:\n", "wow!");
: 452: : 4.49: : wow!:

The same width rule applies to every conversion — integers, floating point, and strings alike. Left alignment and zero padding are not part of width; they are flags, and they arrive in Section 06.

Why width exists

Equal widths on every row are what turn a stream of numbers into a table. %8d on each column gives every value the same amount of horizontal space, so the digits line up.

05The second control: precision

Precision is a dot followed by a number, written after the width if a width is present: %.2f, %10.2f. Unlike width, precision means something different for each family of conversions.

5.1 What precision means per conversion

ConversionMeaning of precisionExample
IntegerMinimum number of digits.%.6d → 000452
f, e, EDigits after the decimal point.%.2f → 4.49
g, GSignificant digits.%.4g
sMaximum bytes written from the string.%.5s → first five bytes
printf(":%.6d:\n", 452);
printf(":%.2f:\n", 4.49);
printf(":%.0f:\n", 4.49);
printf(":%.5s:\n", "wOw!Really Great!");
:000452: :4.49: :4: :wOw!R:
One dot, two opposite jobs

For an integer, precision is a minimum digit count and can only make the result longer. For a string, precision is a maximum byte count and can only make the result shorter. For floating point, it fixes the number of fractional digits exactly.

5.2 Precision changes the text, not the value

double p = 4.49;

printf("%.0f\n", p);
printf("%.1f\n", p);
printf("%.4f\n", p);
4 4.5 4.4900

The stored double is untouched. Precision only decides how many of its digits appear, rounding the displayed result when digits are dropped.

5.3 Precision zero on an integer zero produces nothing

printf(":%.0d:\n", 0);
printf(":%.0d:\n", 452);
:: :452:

“At least zero digits” is satisfied by no digits at all, so the value 0 disappears entirely. Any non-zero value still needs its own digits and is printed in full.

06The third control: flags, one at a time

Flags modify the presentation of a conversion. They appear immediately after %, before any width. This section introduces each flag on its own; Section 07 covers what happens when several are used together.

FlagMeaningExampleTypical result
-Left-align inside the field.%-8d452     
+Always show a sign for a signed numeric conversion.%+d+452
spacePrefix a positive signed value with one blank.% d 452
0Pad a supported numeric field with leading zeroes.%08d00000452
#Request an alternative representation where the conversion defines one.%#x0x1c4

6.1 - — left alignment

The flag only has a visible effect when there is a field wider than the result, because it decides which side the padding goes on.

printf(":%8d:\n",  452);
printf(":%-8d:\n", 452);
: 452: :452 :

6.2 + — always show the sign

printf(":%d:\n",   452);
printf(":%+d:\n",  452);
printf(":%+d:\n", -452);
:452: :+452: :-452:

A negative value already prints its sign. The flag only adds the + that a positive value would otherwise omit.

6.3 space — a blank where the + would be

printf(":% d:\n",  452);
printf(":% d:\n", -452);
: 452: :-452:

This keeps a column of positive and negative numbers aligned without printing a plus sign.

6.4 0 — pad the field with zeroes

printf(":%08d:\n",  452);
printf(":%08d:\n", -452);
:00000452: :-0000452:

The zeroes are inserted after the sign, never before it, so the result still reads as a number.

6.5 # — alternative form

Where a conversion defines an alternative representation, # requests it. For the base conversions that means a base prefix.

printf(":%x:\n",  452u);
printf(":%#x:\n", 452u);
printf(":%#o:\n", 452u);
:1c4: :0x1c4: :0704:

Section 08 covers the base conversions themselves, and Section 09 shows the other use of #: forcing a decimal point onto a floating-point result that has no fractional digits.

Flags are per conversion

A flag exists only where the conversion defines a meaning for it. # means something for %o, %x, %X, %f, %e, and %g; it means nothing for %d or %i. +, space, and 0 belong to numeric conversions, not to %s. Section 7.7 shows what compilers say about the invalid combinations.

07Putting flags, width, and precision together

Each control is simple on its own. The interesting part is what happens when two of them ask for opposite things in the same conversion. Every rule below is verified.

GCC 14.2 and Clang 17 produced identical runtime output

7.1 Flag order is flexible

The flags form a set. Their textual order does not change their meaning. These are equivalent:

printf("%+08d\n", 452);
printf("%0+8d\n", 452);
+0000452 +0000452

The same idea applies to %-+8d and %+-8d: both request an explicit sign and left alignment.

7.2 When - and 0 meet, - wins

printf(":%0-8d:\n", 452);
printf(":%-08d:\n", 452);
:452 : :452 :

Both GCC 14.2 and Clang 17 warn that the 0 flag is ignored when - is present. Left alignment needs padding on the right, so leading zero padding no longer makes sense.

The rule is not specific to integers. A floating-point conversion behaves the same way:

printf(":%-020.10f:\n", 0.0000007856546631);
:0.0000007857 :

7.3 When + and the space flag meet, + wins

printf(":%+ d:\n", 452);
printf(":% +d:\n", 452);
:+452: :+452:

The explicit + is stronger than the “blank for positive values” rule, so the space flag is ignored.

7.4 For integers, precision overrides the 0 flag

printf(":%08.5d:\n", 452);
printf(":%8.5d:\n", 452);
: 00452: : 00452:

Once an explicit precision is given for an integer conversion, the 0 flag is ignored. Precision supplies the minimum digit count; ordinary field padding supplies the remaining spaces. This is the reason to read %08.5d as “five digits inside a field of eight”, not as “two kinds of zero padding”.

7.5 The order of operations inside one conversion

Every example so far follows the same three steps, which is worth stating once:

  1. The specifier converts the value to digits or bytes.
  2. Precision adjusts that result — padding integer digits, fixing fractional digits, or truncating a string.
  3. Width pads whatever remains, on the left by default or on the right under -, with spaces unless 0 applies.
printf(":%20.5s:\n", "wOw!Really Great!");
: wOw!R:

Precision cuts the string to five bytes first; width then aligns those five bytes inside a twenty-character field.

7.6 Width and precision can be supplied at run time with *

int width = 10;
int digits = 3;
double x = 12.34567;

printf("|%*.*f|\n", width, digits, x);
| 12.346|

The width and precision values are taken from preceding int arguments, in the order the * characters appear.

Negative dynamic width

printf("|%*d|\n", -8, 452);
|452 |

A negative width supplied through * means left alignment with the corresponding positive width — exactly as if the - flag had been written.

Negative dynamic precision

printf("|%.*f|\n", -1, 12.34567);
|12.345670|

A negative precision supplied through * is treated as though the precision were omitted, so %f falls back to its default six digits after the decimal point.

7.7 A flag can be valid for one conversion and invalid for another

Important distinction

%+20s, %020s, and %#i are not clever formatting tricks. They use flags for conversions where those flags have no defined meaning. Clang diagnoses these as format strings whose behavior is undefined. GCC also warns.

On the tested glibc runtime, %+20s happened to behave like %20s and %020s also happened to use spaces. That observation is useful for understanding what you may see during an experiment, but it is not a rule to teach or rely on.

08Integer formatting in detail

With all three controls in hand, the rest of the output chapters simply apply them to one data type at a time. This section uses the exact variables from the reference program:

int a = 10, b = 452, c = -56465, d = 45646546;

8.1 The other bases: octal and hexadecimal

unsigned int x = 452;

printf("decimal     : %u\n", x);
printf("octal       : %o\n", x);
printf("hex         : %x\n", x);
printf("HEX         : %X\n", x);
printf("alt octal   : %#o\n", x);
printf("alt hex     : %#x\n", x);
printf("alt HEX     : %#X\n", x);
decimal : 452 octal : 704 hex : 1c4 HEX : 1C4 alt octal : 0704 alt hex : 0x1c4 alt HEX : 0X1C4

The three base conversions take an unsigned int. The # flag from Section 6.5 adds the prefix that makes the base unambiguous when the result is read back.

8.2 Alternative form combined with width, precision, and zero

printf("%#x\n", 0u);
printf("%#08x\n", 452u);
printf("%#08o\n", 452u);
printf(":%#.0o:\n", 0u);
0 0x0001c4 00000704 :0:

Hexadecimal prefixes are not added for a zero value. With zero padding, the 0x prefix is placed before the padding zeroes, so the prefix stays readable. The last line is the one exception to Section 5.3: precision zero normally erases an integer zero, but octal alternative form still guarantees the leading 0.

%#i is not valid alternative-form output

The # flag has no defined meaning for %i. In the test run glibc happened to print the same decimal result, but Clang explicitly diagnosed the combination as undefined behavior. Use %#o, %#x, or %#X for base prefixes.

09Floating-point formatting in detail

First rule

In calls to printf, a float argument is promoted to double. Therefore %f and %lf produce the same output role in printf. In scanf, however, %f requires float * and %lf requires double *. Section 11 explains why the two directions differ.

This section uses the exact values from the reference program:

float p = 4.49f;
float q = -0.00000005f;
float r = 100005.21454f;
float t = 78565465e-14f;

9.1 The default is six digits after the decimal point

printf(":%f:\n",  p);
printf(":%lf:\n", p);
printf(":%.1f:\n", p);
printf(":%.4f:\n", p);
:4.490000: :4.490000: :4.5: :4.4900:

%f and %lf are interchangeable here, which is exactly what the promotion rule predicts. Precision, as in Section 5.2, rounds the displayed result without touching the stored value.

9.2 Scientific notation with %e and %E

printf(":%e:\n",   q);
printf(":%.1e:\n", q);
printf(":%.1E:\n", q);
:-5.000000e-08: :-5.0e-08: :-5.0E-08:

Precision counts the digits after the point in the mantissa. The only difference between %e and %E is the case of the exponent letter — and, for %x versus %X, the same convention held in Section 08.

9.3 Negative zero can appear

printf(":%f:\n",   q);
printf(":%.0f:\n", q);
:-0.000000: :-0:

q is a very small negative value. When rounded to six decimal places it becomes -0.000000, and with zero fractional digits it becomes -0. The sign survives even when the displayed magnitude rounds to zero, which is a formatting artefact rather than an error.

9.4 # forces the decimal point

printf("%.0f\n",  4.49);
printf("%#.0f\n", 4.49);
4 4.

This is the floating-point meaning of the same # flag that produced 0x in Section 8.1: keep the mark that says what kind of value this is, even when it looks redundant.

9.5 Why the stored value may surprise you

printf("%20.10f\n", r);
100005.2109375000

The literal 100005.21454 is converted to float when assigned to r. On the tested platform, the nearest stored value prints as 100005.2109375000 once enough decimal places are requested. Formatting does not create that error; a wide precision merely reveals the approximation that was already stored.

10String output formatting

Strings use the same width and precision slots, with the precision meaning from Section 5.1: a maximum, not a minimum.

char s[]   = "wow!";
char ss[]  = "wOw!Really Great!";
char sss[] = "100% accurAte! Handsome! Awesome! Speechless!";

10.1 Width right-aligns a short string

printf(":%20s:\n", s);
printf(":%20s:\n", ss);
printf(":%20s:\n", sss);
: wow!: : wOw!Really Great!: :100% accurAte! Handsome! Awesome! Speechless!:

Width is a minimum. The long third string is printed completely rather than being truncated.

10.2 Left alignment

printf(":%-20s:\n", s);
:wow! :

10.3 Precision limits how much of the string is written

printf(":%20.5s:\n", ss);
printf(":%-20.5s:\n", ss);
: wOw!R: :wOw!R :

Precision is applied first to obtain at most five bytes; width then aligns that shortened result inside a 20-character field — the order of operations from Section 7.5.

10.4 Exact behavior of the experimental invalid flags

The reference code deliberately tries %020s, %+20s, and %-020s. Both GCC and Clang warn. Clang specifically says the unsupported flag combinations result in undefined behavior.

On this tested glibc run: %020s happened to look like %20s %+20s happened to look like %20s %-020s happened to look like %-20s
Do not convert an observation into a language rule

The runtime output above is only what this implementation happened to do. Portable C code should use %20s, %-20s, %20.5s, or %-20.5s.

11.1 Why output is forgiving and input is not

This is the single most important thing to understand about the length slot, and it is also the bridge into the input chapters that follow.

Output passes values

Default argument promotion converts every char and short to int, and every float to double, before printf sees it. So %d already handles char and short, and %f already handles both float and double. The modifier is only genuinely required for types wider than int, such as long and long long.

Input passes addresses

No promotion applies to a pointer. scanf writes exactly as many bytes as the conversion says, at the address you supply. If the modifier does not match the destination, the wrong number of bytes is written and the behavior is undefined.

short  h;
long   L;
double d;
float  f;

/* input: the modifier must match the destination exactly */
scanf("%hd", &h);    /* short *       */
scanf("%ld", &L);    /* long *        */
scanf("%lf", &d);    /* double *      */
scanf("%f",  &f);    /* float *       */

/* output: both of these are correct, because f is promoted to double */
printf("%f %f\n", f, d);
The two mistakes that actually happen 
double d;
long   n;

scanf("%f", &d);   /* writes 4 bytes into an 8-byte object */
scanf("%d", &n);   /* writes 4 bytes into an 8-byte object */

Neither is a compile error, but both corrupt the destination. A verified run of the first one stored a value that read back as 0.000000. Both compilers do warn with -Wall:

warning: format specifies type 'float *' but the argument has type 'double *' warning: format specifies type 'int *' but the argument has type 'long *'

This is also why %lf is required for reading a double even though %f is enough for printing one.

The one you will need constantly

strlen, sizeof, and the array-counting idiom all produce size_t, whose width is not guaranteed to match unsigned int. Print it with %zu, never with %d or %u.

12Character and simple string I/O

Input starts with the smallest unit there is: one character at a time, with no format string involved.

12.1 getchar() and putchar()

#include <ctype.h>
#include <stdio.h>

int main(void)
{
    int ch;

    while ((ch = getchar()) != EOF) {
        putchar(toupper((unsigned char) ch));
    }

    return 0;
}
Why int ch, not char ch?

getchar() needs to represent every possible unsigned-character value plus the separate sentinel EOF. Store its result in int. Section 14 explains EOF in full.

12.2 putchar(c) and printf("%c", c)

Both can output one character. putchar is the direct character-output function; printf is useful when the character is part of a larger formatted record.

12.3 puts() appends a newline automatically

puts("-----------------------------");
printf("-----------------------------\n");

These produce the same visible line. The difference is that the newline is implicit in puts.

12.4 A character can also be formatted as an integer

char ch = 'g';
printf("character = %c, numeric code = %d\n", ch, (unsigned char) ch);
character = g, numeric code = 103

The value 103 is what the tested ASCII-based execution environment uses for 'g'. A character is simply a small integer, and either view of it can be printed. Section 17 puts this fact to work when arithmetic is done on the bytes of a string.

13Formatted input with scanf

The format string now runs in the other direction. The specifiers are the ones from Section 03; what changes is that width becomes a maximum and that every destination is an address.

13.1 Field width and assignment suppression

Given:

63458465321654
int a, b, c, d;
int count = scanf("%1d%2d%*3d%4d%d", &a, &b, &c, &d);
ConversionCharacters consumedStored result
%1d6a = 6
%2d34b = 34
%*3d584No assignment
%4d6532c = 6532
%d1654d = 1654
count = 4 a = 6, b = 34, c = 6532, d = 1654

One long run of digits is cut into four values purely by the widths. The suppressed conversion consumes input but is not counted as an assignment, which is why count is 4 and not 5.

13.2 Base-specific input: %o, %x, %X, and %d

With the exact reference input:

065355 0X4fFbFd 0xd 0123
unsigned int a, b, c;
int d;

scanf("%o%x%X%d", &a, &b, &c, &d);
decimal values: 27373 5241853 13 123

Each conversion decides the base by itself; the text does not have to carry a prefix. The final token 0123 is read by %d, so it is decimal 123 — the leading zero does not make %d switch to octal.

13.3 The same input with %i gives a different last value

int a, b, c, d;
scanf("%i%i%i%i", &a, &b, &c, &d);
27373 5241853 13 83

%i detects the prefix: 065355 and 0123 are octal, while 0X4fFbFd and 0xd are hexadecimal. This is the one place where %d and %i genuinely differ.

13.4 Reformatting the parsed values

printf("a=%o, b=%x, c=%i, d=%X\n", a, b, (int)c, (unsigned)d);
printf("a=%#o, b=%#x, d=%#X\n", a, b, (unsigned)d);
a=65355, b=4ffbfd, c=13, d=7B a=065355, b=0x4ffbfd, d=0X7B

The value stored in memory is just a number. The base is a property of the text, chosen independently on the way in and on the way out.

13.5 Correct pointer types are part of the format contract

Type mismatch

%o, %x, and %X expect unsigned int * unless a length modifier says otherwise. The original experiment used int *; that is a format-type mismatch even when int and unsigned int happen to have the same representation size. Section 11 is the rule this follows.

13.6 Whitespace behavior is conversion-dependent

  • Most numeric conversions and %s skip leading whitespace automatically.
  • %c, %[, and %n do not automatically skip leading whitespace.
  • A whitespace character inside the format string means “skip any amount of input whitespace.”

13.7 Always check the return value

int x;
if (scanf("%d", &x) == 1) {
    printf("Read: %d\n", x);
} else {
    printf("Invalid integer input.\n");
}

scanf reports the number of successful assignments. Input failure before the first conversion may produce EOF. Section 14 turns that single sentence into a complete rule.

14End of input and EOF

Every input function needs a way to report “there is nothing left to read.” In C that report is the macro EOF, defined in <stdio.h>.

14.1 What EOF actually is

  • It is a macro, not a keyword, and it expands to a negative int constant. On virtually every implementation that value is -1.
  • It is not a character. No byte in a file is “the EOF byte.” It is a sentinel that input functions return in place of a character.
  • It signals two different situations: the input is exhausted, or a read error occurred. For keyboard and redirected input the first is what you will see in practice.
Why the result must be stored in int

getchar returns any of the 256 possible unsigned-character values plus the distinct sentinel EOF. That is 257 outcomes, which cannot fit in a type holding 256 values. Storing the result in char breaks the loop in one of two ways: where char is signed, a legitimate byte 0xFF becomes -1 and ends the loop early on binary data; where char is unsigned, the value can never equal a negative EOF and the loop never ends.

Broken

char ch;
while ((ch = getchar()) != EOF)

Correct

int ch;
while ((ch = getchar()) != EOF)

14.2 Producing end of input at a terminal

When a program reads from the keyboard, nothing ends the input until you say so.

SituationHow to signal end of input
Linux and macOS terminalPress Ctrl+D at the start of an empty line
Windows consolePress Ctrl+Z, then Enter
Redirected file./program < data.txt — end of file arrives automatically
Piped inputprintf 'hi\n' | ./program — end of input arrives when the writer closes

Pressing Ctrl+D in the middle of a typed line flushes what is buffered instead of ending the stream, which is why the convention is to press it on a fresh line.

14.3 The character-counting loop

#include <stdio.h>

int main(void)
{
    int  ch;
    long chars = 0, lines = 0;

    while ((ch = getchar()) != EOF) {
        chars++;
        if (ch == '\n') {
            lines++;
        }
    }

    printf("%ld characters, %ld lines\n", chars, lines);
    return 0;
}

Run against a two-line file containing hi and there:

9 characters, 2 lines

Nine characters, because both newline characters are counted. The assignment inside the condition is deliberate and idiomatic: read, store, and test in one step. The inner parentheses are required, since != binds more tightly than =.

14.4 The three possible scanf return values

scanf does not return the value it read. It returns a count, and the count has three distinct cases that must not be confused.

Return valueNameMeaningState of the input
A positive numberSuccessThat many conversions were assignedConsumed
0Matching failureInput arrived but did not fit the conversion, for example letters for %dNot consumed — the offending text is still waiting
EOFInput failureEnd of input, or a read error, before the first conversion completedNothing left
Zero is not end of input

Treating 0 and EOF as the same condition is the classic cause of a program that hangs. On a matching failure the bad characters stay in the buffer, so a loop that simply retries scanf reads the same bad characters forever.

#include <stdio.h>

int main(void)
{
    int x, r;

    while ((r = scanf("%d", &x)) == 1) {
        printf("read %d\n", x);
    }

    if (r == 0) {
        printf("stopped: input was not a number\n");
    } else {
        printf("stopped: end of input\n");
    }
    return 0;
}

With the input 10 20 abc:

read 10 read 20 stopped: input was not a number

With the input 10 20 followed by end of input:

read 10 read 20 stopped: end of input

14.5 Recovering from a matching failure

To keep reading after bad input, discard the offending text yourself before trying again.

int x, r;

while ((r = scanf("%d", &x)) != EOF) {
    if (r == 1) {
        printf("read %d\n", x);
    } else {
        int junk;
        while ((junk = getchar()) != '\n' && junk != EOF) {
            ;   /* throw away the rest of the offending line */
        }
        printf("skipped invalid entry\n");
    }
}
printf("end of input\n");

Given the input lines 10, zz, and 30:

read 10 skipped invalid entry read 30 end of input

The loop now terminates on EOF alone, and the matching-failure branch guarantees forward progress by consuming at least the rest of the line.

14.6 Reading words until the input ends

The same EOF test drives a string loop. %s reads one whitespace-delimited word, so the loop below consumes the entire input one word at a time regardless of how the words are spread across lines.

#include <stdio.h>

int main(void)
{
    char word[100];
    int  count = 0;

    while (scanf("%99s", word) != EOF) {
        count++;
        printf("word %d: %s\n", count, word);
    }

    printf("total %d words\n", count);
    return 0;
}

Given the two lines alpha beta and gamma:

word 1: alpha word 2: beta word 3: gamma total 3 words
Two details in that format string

The width 99 is not optional: word holds 100 characters, so at most 99 may be read to leave room for '\0'. A leading space, as in " %99s", is harmless but unnecessary — %s already skips leading whitespace on its own, including the newlines between lines.

14.7 Reading a whole line, spaces included

%s stops at the first space, so it cannot read a full sentence. The negated scanset %[^\n] reads everything up to, but not including, the next newline.

#include <stdio.h>

int main(void)
{
    char line[100];

    while (scanf(" %99[^\n]", line) != EOF) {
        printf("[%s]\n", line);
    }

    printf("done\n");
    return 0;
}

Given three lines of input:

[first line here] [second line] [third] done
The leading space is mandatory here

A scanset does not skip leading whitespace, unlike %s and the numeric conversions. Without the space, %[^\n] stops at the first newline and leaves it in the buffer; the next call then finds that newline waiting, matches nothing, and returns 0 forever. Because the loop tests against EOF rather than 1, it never exits.

while (scanf("%99[^\n]", line) != EOF)   /* no leading space */
    printf("[%s]\n", line);

A verified run prints the first line once, then repeats it endlessly because line is never updated again:

r=1 [first line here] r=0 [first line here] r=0 [first line here] r=0 [first line here] ...

The leading space consumes the pending newline before the scanset starts, which fixes it. Testing == 1 instead of != EOF would also stop the loop, though it would stop on a blank line too.

Section 15 covers scansets in full, including positive sets, negated sets, and the whitespace behavior described here.

14.8 EOF across the input functions

FunctionValue when the input endsCorrect loop test
getcharEOFwhile ((ch = getchar()) != EOF)
scanf reading numbersEOFwhile (scanf("%d", &x) == 1)
scanf reading wordsEOFwhile (scanf("%99s", word) != EOF)
scanf reading linesEOFwhile (scanf(" %99[^\n]", line) != EOF)
One habit covers all of them

Never test for end of input separately from the read. Capture what the input function returned, compare it against that function's own failure value, and let that comparison drive the loop.

Coming later in the course

EOF reports either a genuine end of input or a read error, and the two library predicates that tell them apart, feof and ferror, take a stream argument. They belong with data files, later in the learning path, along with the reason while (!feof(...)) is the wrong shape for a read loop.

15String pattern matching with scansets

A scanset uses %[...]. It reads a consecutive sequence of characters selected by the set and then appends a null terminator to the destination array. Section 14.7 already used one; this section covers the notation in full.

15.1 Positive scanset

char s[100];
scanf("%99[a-z]", s);

This accepts up to 99 consecutive lowercase letters. Width 99 leaves one byte for '\0'.

15.2 Negated scanset

Given the input:

sfsad RRRG;
char s[100];
scanf("%99[^a-d]", s);
sfs

The leading ^ means “accept anything except the listed set.” Reading stops immediately before the first a, b, c, or d.

15.3 The exact chained scanset experiment

Starting with:

sfsad RRRG; - dkdfjalkds

The first conversion:

scanf("%[^a-d]", s);

stores sfs and leaves the first a unread. The next conversion:

scanf("%[-a-d; GR]", ss);

starts at that a. Because the leading - is treated as a literal hyphen in this scanset and a-d is a range, the accepted characters are the hyphen, a through d, semicolon, space, G, and R.

s = :sfs: ss = :ad RRRG; - d: remaining input begins with :kdfjalkds:

This exact result was confirmed under both tested runtimes.

15.4 Scansets do not skip leading whitespace automatically

If the next unread character is a space and space is not in the scanset, the conversion fails immediately. Add a space before the conversion in the format string when you intentionally want to skip input whitespace first:

scanf(" %99[a-z]", s);

15.5 Why %[] is malformed

Both GCC and Clang warn that "%[]" has no closing ] for a valid scanset specification. In the local experiment it returned zero assignments and left the destination unchanged, but malformed format specifications must not be used as a programming technique.

Practical rule

Always give string and scanset input a width that leaves room for the terminating null byte: %99s or %99[...] for a 100-byte array.

16Formatted I/O with strings: sscanf, sprintf, and snprintf

Everything so far has read from stdin and written to stdout. The same format-string machinery also works on character arrays in memory. sscanf parses from a string exactly as scanf parses from the keyboard, and sprintf/snprintf format into a buffer exactly as printf formats to the screen. Every rule from Sections 03–15 — specifiers, width, precision, scansets, return values — carries over unchanged; only the source and destination differ.

16.1 sscanf: parse text already stored in memory

char text[] = "ID=42 CGPA=3.75";
int id;
double cgpa;

int count = sscanf(text, "ID=%d CGPA=%lf", &id, &cgpa);
count = 2 id = 42 cgpa = 3.75

The literal characters ID= and CGPA= in the format string must match the input exactly; only the conversions produce values. The three-way return-value logic from Section 14.4 applies unchanged: a positive count, 0 on a matching failure, EOF when the string is exhausted before the first conversion.

16.2 sprintf: format into a character array

char buffer[100];
int count = sprintf(buffer, "x = %d", 203);
buffer = x = 203 count = 7

The return value is the number of characters written before the terminating null character. sprintf itself has no destination-size limit.

16.3 Prefer snprintf when capacity matters

char buffer[8];
int needed = snprintf(buffer, sizeof buffer, "value=%d", 12345);

At most seven visible characters plus the null terminator fit in buffer. The return value reports how many characters would have been produced with unlimited space, which lets you detect truncation by checking whether needed >= sizeof buffer.

Both sprintf and sscanf operate on an array of bytes with a capacity, terminated by a null character. Section 17 examines exactly what that means in memory.

17Embedded null characters, array capacity, and stale bytes

Consider the exact reference array:

char s[] = "Something going to happen, but who knows!\0Oh!";

There are two null bytes in the initialized content: the explicit \0 after the exclamation mark and the implicit terminator added after Oh!.

printf("sizeof = %zu\n", sizeof s);
printf("strlen = %zu\n", strlen(s));
printf("s      = %s\n", s);
sizeof = 46 strlen = 41 s = Something going to happen, but who knows!

sizeof measures the complete array. strlen counts only from the starting address up to the first null byte.

17.1 Critical indices before overwriting

IndexByteMeaning
10'g' / 103 on the tested ASCII systemA character is a small integer, as Section 12.4 showed; x += s[10] below turns 100 into 203.
37'o's + 37 begins the substring ows!.
41'\0'First string terminator.
42–44O h !Bytes physically present in the array but hidden from %s starting at s.
45'\0'Final implicit terminator.

17.2 Pointer arithmetic lets sscanf begin in the middle

Because a C string is just a starting address, sscanf can be handed any position inside the array. The index table above shows that s + 37 points at the o of knows!:

char word[100];

sscanf(s + 37, "%99s", word);
word = ows!

Parsing stops at the first null terminator, index 41, exactly as it would stop at the end of console input.

17.3 What sprintf overwrites — and what it does not

int x = 100;
x += s[10];              /* 203 on the tested ASCII system */
sprintf(s, "x = 100+s[10] = %d", x);
s = x = 100+s[10] = 203 strlen = 19

The new text occupies indices 0 through 18 and sprintf places its null terminator at index 19. It does not clear the rest of the 46-byte array.

printf("s+19 = :%s:\n", s + 19);
printf("s+20 = :%s:\n", s + 20);
s+19 = :: s+20 = :appen, but who knows!:

Index 19 is the new null terminator, so s + 19 is an empty string. Index 20 still contains old data beginning with the a from the original word happen.

Core model

An array is a region of bytes with a capacity. A C string is a view that starts at some byte and ends at the first null byte encountered from that starting point.

19A consolidated, corrected demonstration program

Verification environment

The edge-case programs behind this tutorial were compiled with gcc 14.2.0 and clang 17.0.0 using -std=c17 -Wall -Wextra -Wpedantic -Wformat=2. The two executables produced identical runtime output for the tested cases. Compiler warnings are treated as part of the lesson: a result that happens to print on one C library is not presented as guaranteed behavior when the format itself is invalid.

This program keeps the spirit of the reference code while making the type usage and bounded string operations suitable for teaching. Its sections appear in the same order as the handbook: integer output, floating-point output, string output, then string-based parsing and formatting.

#include <ctype.h>
#include <stdio.h>
#include <string.h>

int main(void)
{
    /* Integer formatting — Section 08 */
    int a = 10, b = 452, c = -56465, d = 45646546;

    printf("Default : %d %d %d %d\n", a, b, c, d);
    printf("Width   : %8d %8d %8d %8d\n", a, b, c, d);
    printf("Zero    : %08d %08d %08d %08d\n", a, b, c, d);
    printf("Sign    : %+08d %+08d %+08d %+08d\n", a, b, c, d);
    printf("Left    : %-8d %-8d %-8d %-8d\n\n", a, b, c, d);

    /* Floating-point formatting — Section 09 */
    double p = 4.49;
    double q = -0.00000005;
    double r = 100005.21454;

    printf("Fixed       : %.6f\n", p);
    printf("Scientific  : %.6e\n", q);
    printf("Width/prec. : %20.10f\n", r);
    printf("Signed/zero : %+020.10f\n\n", p);

    /* String formatting — Section 10 */
    char text[] = "wOw!Really Great!";
    printf("Right   : :%20s:\n", text);
    printf("Left    : :%-20s:\n", text);
    printf("Limit   : :%20.5s:\n\n", text);

    /* sscanf: parse from a string — Section 16 */
    char record[] = "ID=42 CGPA=3.75";
    int id;
    double cgpa;

    if (sscanf(record, "ID=%d CGPA=%lf", &id, &cgpa) == 2) {
        printf("Parsed: id=%d, cgpa=%.2f\n", id, cgpa);
    }

    /* snprintf: format into a bounded array — Section 16 */
    char buffer[100];
    snprintf(buffer, sizeof buffer, "Student %d has CGPA %.2f", id, cgpa);
    printf("Buffer: %s\n", buffer);

    return 0;
}
